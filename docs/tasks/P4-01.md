## Coupon codes (deterministic, src/mocks/coupons.ts)
| Code | Effect |
|---|---|
| `KURIO10` | 10% off subtotal (half-up 18 dp) |
| `LANCAMENTO` | 0.5 ETH off, capped at subtotal |
| `EXPIRADO` | 422 `COUPON_EXPIRED` |
| anything else | 422 `COUPON_INVALID` |

Codes are case-insensitive (normalized upper case). Network fees: ethereum `0.016` (Figma), polygon `0.002`, solana `0.0005` (quotes always use `ethereum`).

## Decisions / contract interpretations
- **Merge location:** login/register forms send `guestCartId` via `withGuestCart()` (`src/features/cart/guest-cart-id.ts`) and `auth-screen` passes `response.cartMerge` to `session.signIn(session, cartMerge)`. One-line edits in `login-form.tsx`, `register-form.tsx`, `auth-screen.tsx` (outside the listed ownership, needed because login is not called by the session manager). `signIn` forgets `kurio.guestCartId` and publishes the merge notice (rendered under the header on every route); logout dismisses it.
- **Merge semantics:** `requested` = user qty + guest qty, `applied` = final qty; the user's own existing quantity is never reduced by a merge; reason `availability` when `available < maxPerOrder`, else `max_per_order`; sold-out/vanished → `unavailable` (dropped). `mergedItems` = guest lines that increased the user cart. Empty/unknown guest cart → `cartMerge: null` (still deleted).
- **Owner on the client:** API calls take an explicit owner (`{kind:'user', token}` → Bearer; `{kind:'guest', guestCartId}` → `X-Guest-Cart-Id` + `skipAuth`), so a request can never fill another owner's cache entry. `src/api/client.ts` was not changed. A guest without an id has an empty cart and no request; the id is created on the first add/coupon.
- **Mutations:** single TanStack mutation scope (serialized), `mutationKey ['cart', ...]`; result replaces `['cart', ownerKey]` only if the owner is unchanged and version not older. Session-manager mutation clearing now removes every non-cart mutation (auth variables) and keeps cart ones.
- **Quote:** query key `['cart', ownerKey, 'quote', {network, cartVersion}]`, `previousQuoteId` = latest cached quote of the owner (404 → retried without it); `refetchOnMount: 'always'` on the cart page; line totals and summary only from the quote for the current cart version. Quotes are owner-scoped in the mock db (another owner's `previousQuoteId` → 404). Changes are emitted for price, availability (when `available` moved below the requested qty), item unavailable, fee, and `coupon_invalidated` whenever the stored coupon fails re-validation.
- **GET /api/cart** for a new owner returns an unsaved empty cart (version 0, id `cart_<userId>` / `cart_guest_<uuid>`); mutation no-ops (same coupon, same quantity, deleting a missing line) do not bump `version`. `POST /api/cart/items` requires an NFT **id** (a slug → 404 `NFT_NOT_FOUND`).
- **Cart page:** Figma CTA text "Conectar e finalizar" kept; rendered with the unavailable pattern until P4-02 adds `/checkout`. DB_SCHEMA_VERSION 3 → 4 (`carts`, `quotes`).
- **Bundle:** header/tab-bar cart link and merge notice load from a lazy chunk (`cart-chrome-impl`) with a static link fallback; entry chunk 507.03 kB (was ~505 kB).
