## Acceptance criteria
- [x] App uses the real `socket.io-client` (`Socket<ServerToClientEvents, ClientToServerEvents>`, websocket transport) loaded in its own chunk; MSW intercepts the WebSocket and the mock speaks Engine.IO v4 / Socket.IO v5 (handshake, CONNECT with `auth.token`, CONNECT_ERROR for bad tokens, ping/pong, events). No cache setters disguised as a transport.
- [x] `nft.updated` broadcast on every NFT version bump (dev patch, order stock reservation/release, reset); `order.updated` only to the owner's sockets on order version bumps (creation, automatic resolution at `resolveAt`, dev resolve).
- [x] Client: zod-validated envelopes; unknown `schemaVersion`/invalid payload → REST reconciliation; `eventId` dedup (bounded); `version > cached` only (stale ignored); orders of another user ignored; terminal order states never regressed; receipts never touched.
- [x] Cache effects: patch summary/detail/featured/related copies; mark lists stale; NFT in cart → cart + quote invalidated → open checkout shows "Os valores do seu pedido mudaram" and must be accepted before confirming; order confirmation → cart + orders list refreshed.
- [x] One socket per session: recreated on login/logout/user switch/expiry (guest socket after logout), listeners removed on cleanup.
- [x] Reconnection: backoff 0.5–2 s; after reconnecting, active catalog/detail, cart/quote and pending orders are refetched (REST wins). Visible `role="status"` banner while reconnecting; polite live region announces changes to an NFT on screen or in the cart.
- [x] Backlog: mock reset keeps NFT versions monotonic; selected edition that sells out falls back to one with stock.
- [x] Entry chunk unchanged (≈510 kB).
