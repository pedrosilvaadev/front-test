## Acceptance criteria
- [x] Mock: `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/session`, `POST /api/auth/logout` exactly per docs/API_CONTRACTS.md and `src/contracts/session.ts` (request/response validated with zod; errors as error envelope: `VALIDATION_ERROR` with field details, `EMAIL_TAKEN`/`USERNAME_TAKEN` (use the codes the contract defines), `INVALID_CREDENTIALS` 401, `UNAUTHORIZED`/`SESSION_EXPIRED` 401). Salted hash via `src/mocks/password.ts`, opaque random tokens with TTL, revoked on logout (idempotent). Sessions survive mock db reload as the design requires and are cleared by `/api/__dev/reset`. Dev control to force-expire a session (e.g. `POST /api/__dev/sessions/expire`). Network scenarios apply to auth endpoints like the rest.
- [x] Client: Axios sends `Authorization: Bearer` when a session exists; token in memory + `localStorage` `kurio.session`; boot calls `GET /api/auth/session` before resolving protected routes (pending state, no flash of private content); invalid/expired stored token → cleared silently, user is guest.
- [x] 401 `SESSION_EXPIRED`/`UNAUTHORIZED` on an authenticated call → cancel+remove `['user']`, `['cart']`, `['session']` queries (ADR-004), clear token, redirect to `/login?redirect=<current URL>` with a visible "Sua sessão expirou" message. `INVALID_CREDENTIALS` handled by the login form only (no redirect loop).
- [x] Logout: `POST /api/auth/logout` (best effort; local logout even if the request fails), clears private caches and token, navigates to `/` (or stays on public pages). Cross-tab: `storage` event on `kurio.session` syncs logout/login in other tabs.
- [x] Routes: `/login` and `/cadastro` with `redirect` search param (validated: only same-origin relative paths starting with `/` and not `//`, else `/`); after success navigate to redirect. Signed-in users visiting `/login`/`/cadastro` are redirected to redirect or `/`. `_authed` layout guards private routes; `/perfil` minimal page showing displayName, username, email and a logout button (data from session, no fake data).
- [x] UI per Figma: desktop = dialog over the Início page with tabs "Entrar | Criar conta" (close returns to previous page or `/`), subtitle, email, password with show/hide toggle, "Esqueceu a senha?" (unavailable), Entrar button, "Ou continue com" + Google/Facebook (unavailable). Cadastro: username, email, password, confirm password (with toggles), "Criar perfil", social (unavailable), "Já tem uma conta? Entre". Mobile = full-page forms with KURIO wordmark. Forms validated client-side with the contract schemas (`loginRequestSchema`, `registerFormSchema`), pt-BR messages, field errors linked via aria-describedby, server field errors mapped to fields, submit disabled + spinner while pending, no double submit, password never persisted.
- [x] Header: "Entrar" opens `/login?redirect=<current>`; signed in → user button (displayName/avatar initials) with menu: Perfil, Sair. Mobile tab bar profile tab → `/perfil` (guard redirects guests to login).
- [x] A11y: labelled inputs, dialog focus trap + Esc, errors announced (role=alert / aria-live), password toggle labelled with aria-pressed.
- [x] Tests: unit (redirect sanitizer, session store, 401 handling clears caches, form validation/error mapping, mock handlers incl. hashing/TTL/revocation); Playwright desktop+mobile: register → lands on redirect signed in; login wrong password error; login → refresh keeps session; protected `/perfil` as guest → login → back to `/perfil`; logout clears and `/perfil` redirects; forced expiry → next authed request redirects to login with message and returns after re-login; two demo users switch (user B never sees user A's data on `/perfil`); open redirect `?redirect=//evil.com` ignored.
- [x] Orchestrator gate: quick gate + `e2e/auth.spec.ts` + specs touched (ADR-008).
